# Slow computer and freezing applications

TEST KNOWLEDGE BASE - Example IT procedure, version 1.0, reviewed 2026-10-10. This is training/test documentation, not an adopted UNIO policy. Applies to Windows 11 unless stated otherwise. Product models, approvals, support contacts, access groups, SLAs and configuration values must be confirmed locally. Never invent them.

## Purpose and symptoms
Use when performance is degraded; distinguish one app from whole-device slowness.

## Before you start
Record the ticket, employee, asset tag, exact symptom/error, when it began, recent changes, and whether other users are affected. Obtain consent before interrupting work. Protect private information; never collect passwords, MFA codes, recovery keys or unrestricted screenshots.

## Procedure
1. Ask which task is slow, how long it takes, when it started and whether it occurs on battery or connected power.
2. Ask the employee to save work; close unused applications and restart at an agreed time.
3. Inspect Task Manager for CPU, memory and disk pressure; record the affected process, not private application content.
4. Check available storage and approved startup applications. Remove files or startup entries only when the employee/IT has authorized the change.
5. Check approved Windows/application updates and run managed security checks. Avoid registry cleaners and random optimization utilities.
6. If one application is affected, compare a small test file and known-working account/device; collect application logs for its owner.

## Verification and ticket closure
Repeat the original task and record whether responsiveness improved. Record the steps attempted, observed result, technician and time in the ticket. Close only after the employee confirms the original task works.

## Stop and escalate
Escalate recurring freezes, unexpected disk errors, thermal shutdown, suspected malware or insufficient hardware for the workload.
