# Printer offline or not found

TEST KNOWLEDGE BASE - Example IT procedure, version 1.0, reviewed 2026-10-10. This is training/test documentation, not an adopted UNIO policy. Applies to Windows 11 unless stated otherwise. Product models, approvals, support contacts, access groups, SLAs and configuration values must be confirmed locally. Never invent them.

## Purpose and symptoms
Use for printer offline, unavailable or absent from the computer.

## Before you start
Record the ticket, employee, asset tag, exact symptom/error, when it began, recent changes, and whether other users are affected. Obtain consent before interrupting work. Protect private information; never collect passwords, MFA codes, recovery keys or unrestricted screenshots.

## Procedure
1. Identify printer model, asset tag, connection type and whether other users can print.
2. Check printer power and visible alerts. Verify the intended USB or approved network connection.
3. Check the selected printer and test another permitted application. Avoid sending sensitive material during testing.
4. For network printers, compare device location/network and record the printer address from its approved configuration; do not invent an address.
5. Use Windows printer diagnostics; ask IT to check the approved queue/driver if discovery fails.
6. Before power cycling a shared printer, confirm with affected users and wait for current jobs to finish.

## Verification and ticket closure
Print a non-sensitive test page from the affected computer and confirm it reaches the intended printer. Record the steps attempted, observed result, technician and time in the ticket. Close only after the employee confirms the original task works.

## Stop and escalate
Escalate shared outages, recurring offline behavior, authentication errors, unfamiliar certificates or unavailable approved drivers.
