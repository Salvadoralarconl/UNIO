# Wi-Fi connected but no internet

TEST KNOWLEDGE BASE - Example IT procedure, version 1.0, reviewed 2026-10-10. This is training/test documentation, not an adopted UNIO policy. Applies to Windows 11 unless stated otherwise. Product models, approvals, support contacts, access groups, SLAs and configuration values must be confirmed locally. Never invent them.

## Purpose and symptoms
Use for no internet, intermittent Wi-Fi or inability to join an approved network.

## Before you start
Record the ticket, employee, asset tag, exact symptom/error, when it began, recent changes, and whether other users are affected. Obtain consent before interrupting work. Protect private information; never collect passwords, MFA codes, recovery keys or unrestricted screenshots.

## Procedure
1. Identify whether one device or several are affected; confirm the approved Wi-Fi name and location.
2. Check airplane mode, Wi-Fi enabled and connection state. Do not join a look-alike network or share credentials.
3. Try the approved network again and test more than one permitted site. Note whether internal services and external internet fail differently.
4. Check VPN state under the approved access policy; never disable security controls as a blanket workaround.
5. With consent, reconnect Wi-Fi or restart the computer. Test approved Ethernet where available.
6. Provide network staff with timestamps, network name, signal behavior and comparison-device results. Only network staff should restart shared routers or change DNS/VLAN settings.

## Verification and ticket closure
Confirm the employee can reach their required application and connectivity stays stable. Record the steps attempted, observed result, technician and time in the ticket. Close only after the employee confirms the original task works.

## Stop and escalate
Escalate multi-user outages, certificate warnings, recurring disconnects or failure of managed network authentication.
