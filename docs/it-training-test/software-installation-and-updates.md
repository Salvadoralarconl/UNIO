# Software installation and updates

TEST KNOWLEDGE BASE - Example IT procedure, version 1.0, reviewed 2026-10-10. This is training/test documentation, not an adopted UNIO policy. Applies to Windows 11 unless stated otherwise. Product models, approvals, support contacts, access groups, SLAs and configuration values must be confirmed locally. Never invent them.

## Purpose and symptoms
Use for installing or updating business software on a managed computer.

## Before you start
Record the ticket, employee, asset tag, exact symptom/error, when it began, recent changes, and whether other users are affected. Obtain consent before interrupting work. Protect private information; never collect passwords, MFA codes, recovery keys or unrestricted screenshots.

## Procedure
1. Confirm the approved software name, version, license and business purpose. Ask the employee to save work.
2. Check compatibility, free space and an approved backup/recovery plan; schedule restarts.
3. Use the organization software portal or verified vendor source. Never use crack tools, random driver sites or unapproved administrator credentials.
4. Install under the approved deployment process and verify the publisher. Do not disable endpoint protection to make installation succeed.
5. Apply required updates; restart with consent and reopen the application.
6. If a change fails, stop and follow the approved rollback procedure rather than repeatedly installing different versions.

## Verification and ticket closure
Confirm the correct version launches, license works and the employee can perform their task. Record the steps attempted, observed result, technician and time in the ticket. Close only after the employee confirms the original task works.

## Stop and escalate
Escalate missing licensing, unsupported OS, security blocks, admin requirements or failed rollback.
