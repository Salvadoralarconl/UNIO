# Security incident and suspicious email

TEST KNOWLEDGE BASE - Example IT procedure, version 1.0, reviewed 2026-10-10. This is training/test documentation, not an adopted UNIO policy. Applies to Windows 11 unless stated otherwise. Product models, approvals, support contacts, access groups, SLAs and configuration values must be confirmed locally. Never invent them.

## Purpose and symptoms
Use for suspected phishing, malware, lost devices or account compromise.

## Before you start
Record the ticket, employee, asset tag, exact symptom/error, when it began, recent changes, and whether other users are affected. Obtain consent before interrupting work. Protect private information; never collect passwords, MFA codes, recovery keys or unrestricted screenshots.

## Procedure
1. Ask the employee to stop interacting with the suspicious content. Do not request passwords or verification codes.
2. Record what happened, timestamps, affected account/device and whether credentials or files were exposed; collect only necessary evidence.
3. Use the approved security reporting channel and create a restricted ticket. Do not send suspicious attachments to other employees.
4. If compromise is actively spreading, follow the security team containment playbook; do not independently wipe, reinstall or delete evidence.
5. For account exposure, have authorized security staff revoke sessions/reset credentials and investigate sign-ins; verify identity through the approved method.
6. Preserve the device and logs according to instructions; document custody and team ownership.

## Verification and ticket closure
Obtain security-team confirmation of containment and authorized return to use. Record the steps attempted, observed result, technician and time in the ticket. Close only after the employee confirms the original task works.

## Stop and escalate
Escalate immediately to security for credential disclosure, unexpected MFA prompts, encryption/ransomware, data exfiltration or a lost managed device.
