# Remote support session and escalation handoff

TEST KNOWLEDGE BASE - Example IT procedure, version 1.0, reviewed 2026-10-10. This is training/test documentation, not an adopted UNIO policy. Applies to Windows 11 unless stated otherwise. Product models, approvals, support contacts, access groups, SLAs and configuration values must be confirmed locally. Never invent them.

## Purpose and symptoms
Use for obtaining consent and handing an unresolved ticket to another technician.

## Before you start
Record the ticket, employee, asset tag, exact symptom/error, when it began, recent changes, and whether other users are affected. Obtain consent before interrupting work. Protect private information; never collect passwords, MFA codes, recovery keys or unrestricted screenshots.

## Procedure
1. Confirm the employee identity, ticket and authorized remote-support tool. Explain the intended work and obtain consent.
2. Ask the employee to close private content; use the least access needed. Never request their password or approval of an unexpected MFA prompt.
3. Keep the employee informed while changing approved settings and obtain consent before restart/disruption.
4. Document the original symptom, environment, reproductions, attempted actions, results and remaining hypothesis.
5. For handoff, assign the ticket to the responsible signed-in technician and attach sanitized logs/screenshots only when needed.
6. End the remote session and confirm the next action with the employee. Do not leave unapproved persistent remote access.

## Verification and ticket closure
Confirm session ended and next owner has enough evidence to continue without repeating work. Record the steps attempted, observed result, technician and time in the ticket. Close only after the employee confirms the original task works.

## Stop and escalate
Escalate unclear consent, unknown identity, sensitive data exposure or a request to bypass access controls.
