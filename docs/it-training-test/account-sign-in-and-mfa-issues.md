# Account sign-in and MFA issues

TEST KNOWLEDGE BASE - Example IT procedure, version 1.0, reviewed 2026-10-10. This is training/test documentation, not an adopted UNIO policy. Applies to Windows 11 unless stated otherwise. Product models, approvals, support contacts, access groups, SLAs and configuration values must be confirmed locally. Never invent them.

## Purpose and symptoms
Use for lockouts, rejected passwords and MFA enrollment/replacement.

## Before you start
Record the ticket, employee, asset tag, exact symptom/error, when it began, recent changes, and whether other users are affected. Obtain consent before interrupting work. Protect private information; never collect passwords, MFA codes, recovery keys or unrestricted screenshots.

## Procedure
1. Record which system is failing and the exact message. Never ask the employee to disclose their password or MFA code.
2. Check keyboard layout, account identifier, time/network connectivity and whether the system is available.
3. Use the approved identity verification process before resetting credentials or enrollment. A display name alone is not identity proof.
4. Direct the verified employee to the approved reset/enrollment flow; obtain administrator help for a managed lockout.
5. If the employee receives MFA prompts they did not initiate, stop normal troubleshooting and report a possible compromise.
6. Have the employee sign in themselves and enroll only their authorized authenticator; record the outcome without secrets.

## Verification and ticket closure
Confirm the employee can sign in, complete MFA and access permitted services. Record the steps attempted, observed result, technician and time in the ticket. Close only after the employee confirms the original task works.

## Stop and escalate
Escalate unknown identity, unexpected sign-ins, lost authentication devices or requests to bypass MFA.
