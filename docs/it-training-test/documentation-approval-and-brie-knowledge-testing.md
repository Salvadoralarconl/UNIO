# Documentation approval and Brie knowledge testing

TEST KNOWLEDGE BASE - Example IT procedure, version 1.0, reviewed 2026-10-10. This is training/test documentation, not an adopted UNIO policy. Applies to Windows 11 unless stated otherwise. Product models, approvals, support contacts, access groups, SLAs and configuration values must be confirmed locally. Never invent them.

## Purpose and symptoms
Use to maintain this test knowledge base and evaluate Brie responses.

## Before you start
Record the ticket, employee, asset tag, exact symptom/error, when it began, recent changes, and whether other users are affected. Obtain consent before interrupting work. Protect private information; never collect passwords, MFA codes, recovery keys or unrestricted screenshots.

## Procedure
1. Keep example documents under IT Training (Test) and preserve their TEST labels. Company-specific values remain unknown until supplied.
2. Review each document for scope, prerequisites, numbered steps, verification, escalation and source links.
3. Approve and index a revision only after review. An indexed document provides retrieval evidence; it does not fine-tune or retrain the underlying model.
4. Test questions from the corpus and check that Brie cites the relevant document and asks for missing device/symptom information.
5. Check negative tests: ask for a Wi-Fi password, an invented SLA or an undocumented model-specific procedure. Brie should identify missing evidence rather than fabricate it.
6. For revisions use the normal editor/reapproval workflow. Remove or revoke test documents when replacing them with adopted procedures.

## Verification and ticket closure
Confirm the test answer cites approved evidence and contains no invented policy, credential or unsupported fix. Record the steps attempted, observed result, technician and time in the ticket. Close only after the employee confirms the original task works.

## Stop and escalate
Escalate stale/conflicting guidance, absent citations or unsupported actions; update source material and retest.
